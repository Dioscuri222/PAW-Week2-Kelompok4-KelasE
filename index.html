1. Fokus Penelitian (Membahas Apa?)

Masalah yang Diangkat

Akses terhadap rujukan fatwa fiqih kontemporer sering kali terkendala tebalnya literatur kitab, keterbatasan waktu membaca, dan kompleksitas bahasa hukum Islam bagi masyarakat awam maupun mahasiswa. Sementara itu, dinamika persoalan modern menuntut fatwa praktis yang responsif dan kontekstual.

Solusi yang Dibangun: Chatbot RAG Fiqih (Text-Only)

Penelitian ini mengembangkan Question Answering System (QAS) berbasis web dengan arsitektur Retrieval-Augmented Generation (RAG) modalitas teks tunggal (text-only generation):

1. Korpus Data: Mengonversi 9 buku karya Syekh Yusuf Al-Qardhawi ke format PDF.
2. Vektorisasi: Pemotongan teks (chunking) dan konversi ke vektor via model embedding-001 Google, lalu diindeks ke basis data vektor FAISS.
3. Retrieval & Jawaban: Kueri teks dicocokkan untuk mengambil 3 potongan teratas (Top-3 chunks), lalu disintesis secara kontekstual oleh Gemini-2.0-flash via orkestrasi LangChain.
4. Antarmuka: Dibangun menggunakan framework Streamlit.

2. Kekuatan & Keunggulan Penelitian

Validasi Ganda (Ahli & Evaluator Otomatis)

Pengujian memadukan User Acceptance Test (UAT) langsung oleh pakar fiqih (skor 89,00%) serta evaluasi kuantitatif otomatis kesesuaian rujukan menggunakan LangChain Scoring Evaluator (skor rata-rata 95,00%).

Inferensi Cepat & Penalaran Kontekstual

Penerapan arsitektur Gemini-2.0-flash memberikan waktu inferensi yang gesit (low latency) dengan pemahaman semantik bahasa alami yang memadai untuk bahasa Indonesia formal.

Grounding Fatwa Otoritatif

Jawaban dikunci (grounded) pada literatur Al-Qardhawi dengan menyertakan kutipan sumber sehingga meminimalkan bias atau fabrikasi jawaban (halusinasi AI).

3. Kelemahan & Keterbatasan Metodologis

Bias Sumber Tunggal (Single-Scholar Limitation)

Basis rujukan hanya mengambil pandangan satu ulama tanpa membandingkan perspektif 4 madzhab besar (Hanafi, Maliki, Syafi'i, Hanbali) maupun fatwa majelis tarjih/MUI lokal.

Ukuran Sampel Uji Sangat Terbatas (Small Sample Size)

Pengujian hanya melibatkan 10 butir pertanyaan dan 7 responden, belum mencakup skenario pertanyaan jebakan atau kasus fiqih yang ambigu (*edge-cases*).

Fokus Masalah 1 yang Dipilih

Skalabilitas Antarmuka Web Rendah (Streamlit)

Framework Streamlit sangat cocok untuk prototipe cepat, namun memiliki kendala konkurensi bawaan karena arsitektur eksekusi ulang skrip (rerun script) yang rentan kehabisan memori saat diakses serentak oleh puluhan hingga ratusan pengguna.

Fokus Masalah 2 yang Dipilih

Ketergantungan Penuh pada Cloud API Pihak Ketiga

Keterikatan (vendor lock-in) pada ekosistem Google AI API mengharuskan koneksi internet aktif terus-menerus dan biaya pemanggilan API berkelanjutan tanpa adanya opsi arsitektur fallback model luring (open-source/on-premise) jika kuota habis atau jaringan terputus.

4. Solusi Usulan Terhadap Masalah yang Dipilih

Fokus Perbaikan: Menyelesaikan kendala skalabilitas konkurensi Streamlit serta ketergantungan API pihak ketiga dengan arsitektur tangguh dan ramah hardware lokal (VRAM 4 GB).

Solusi 1: Dekopling Arsitektur (FastAPI + Asynchronous Worker + Semantic Cache)

Mengatasi Masalah: Skalabilitas Antarmuka Web Rendah.

• Migrasi ke FastAPI: Memisahkan backend menjadi REST API asinkron menggunakan FastAPI dan worker Uvicorn yang mampu melayani ribuan koneksi konkuren non-blocking.
• Pemisahan Frontend: Menggunakan antarmuka web statis ringan yang dapat di-hosting pada CDN tanpa membebani server komputasi.
• Semantic Cache (Redis): Kueri fatwa berulang (hukum shalat, puasa, wudhu) disimpan di Redis untuk merespons instan (<50 ms) tanpa memanggil ulang FAISS maupun LLM.

Solusi 2: Arsitektur Hybrid Failover Router Menggunakan SLM (Small Language Model) Lokal

Mengatasi Masalah: Ketergantungan Penuh pada Cloud API Gemini.

• Smart Router: Menjadikan Google Gemini 2.0 Flash sebagai pemroses utama di cloud. Jika limit kuota habis (HTTP 429) atau koneksi internet terputus, sistem otomatis mengalihkan tugas ke mesin lokal.
• Model Fallback Ringan (Hemat Memori): Memanfaatkan Small Language Model terkuantisasi 4-bit seperti Qwen 2.5 3B-Instruct atau Gemma E2B / Gemma 3 4B (Q4) yang hanya mengonsumsi VRAM ~2,0–2,5 GB. Model ini dapat berjalan stabil di laptop tim dengan GPU 4 GB karena VRAM Terbatas.
• Offline Vector Retrieval: Menggunakan model embedding lokal open-source (seperti paraphrase-multilingual-MiniLM-L12-v2 atau bge-small) sehingga fungsi pencarian semantik tetap bekerja tanpa internet.

Peringatan Metodologis & Batasan Fiqih

Fatwa hukum Islam menyangkut ranah keyakinan dan peribadatan personal. Meskipun chatbot berbasis RAG menghasilkan akurasi tinggi, model AI tidak dapat menggantikan otoritas fatwa ulama secara mutlak.

Tingginya akurasi dalam penelitian ini dipengaruhi oleh sempitnya cakupan dokumen (9 buku dari 1 ulama). Implementasi publik yang kredibel membutuhkan validasi fatwa komparatif lintas madzhab.
