Dokumentasi Rekayasa Perangkat Lunak

Spesifikasi Diagram & Visualisasi Arsitektur Sistem

Visualisasi rinci perancangan sistem chatbot tanya jawab Fiqih Kontemporer RAG, mencakup diagram arsitektur pipeline, interaksi aktor (Use Case), struktur kelas OOP, serta alur eksekusi pesan (Sequence Diagram).

1. Diagram Arsitektur Sistem (Alur Utama RAG)

Deskripsi Visualisasi Arsitektur

Diagram ini menggambarkan 5 tahapan utama dalam memproses pertanyaan fiqih dari data mentah hingga menjadi jawaban kontekstual:

Poin Arsitektur:

  • Tahap 1 (Indexing Offline): 9 Buku PDF karya Syekh Al-Qardhawi di-chunk dan di-embed dengan model Google embedding-001 lalu disimpan ke Vector DB FAISS.
  • Tahap 2 & 3 (Web UI & Backend): Antarmuka Streamlit meneruskan kueri pengguna ke LangChain untuk melakukan similarity search (Top-3 context).
  • Tahap 4 (Generative Engine): Model Gemini 2.0 Flash merangkum jawaban berdasarkan 3 potongan teks rujukan.
  • Tahap 5 (Evaluasi): Menampilkan hasil pengujian UAT Pakar (89%) dan LangChain Scoring (95%).

2. Use Case Diagram (Aktivitas Aktor & Fallback)

Deskripsi Peran & Fitur Sistem

Diagram ini memetakan batasan sistem, hak akses antara **Pengguna** dan **Admin/Pengembang**, serta mekanisme perluasan fungsi (*include* & *extend*).

Poin Use Case:

  • Aktivitas Pengguna: Mengajukan pertanyaan, melihat jawaban & kutipan rujukan kitab, serta melihat provider model AI yang sedang aktif.
  • Mekanisme Relasi (Include): Setiap pengajuan pertanyaan secara otomatis memicu proses Cache & Pembatasan Laju, Pencarian Kemiripan FAISS, dan Generasi Jawaban LLM.
  • Mekanisme Relasi (Extend): Apabila koneksi internet terputus atau limit API tercapai, sistem memperluas eksekusi ke Fallback Model Lokal Ollama secara transparan.
  • Aktivitas Admin: Mengunggah PDF kitab baru, mengonfigurasi rantai model fallback, serta menjalankan skrip *ingest* dataset.

3. Class Diagram (Struktur Objek & Kode Backend)

Deskripsi Arsitektur Berbasis Objek (OOP)

Diagram kelas memperlihatkan modulasi komponen kode internal Python yang saling terhubung untuk menjalankan fungsi RAG dan evaluasi.

Poin Komponen Kelas:

  • ChatbotUI: Mengelola rendering antarmuka pengguna (sidebar, chat history, loading indicator).
  • ChatEngine: Kelas orchestrator utama yang menghubungkan EmbeddingManager, VectorStoreManager, dan GeminiLLMService.
  • PDFProcessor & TextSplitter: Menangani ekstraksi file PDF dan pemotongan teks menjadi DocumentChunk.
  • QADataResponse & Reference: Mengapsulasi data keluaran jawaban beserta rujukan halaman PDF kitab.
  • SystemEvaluator: Modul khusus untuk menghitung skor UAT dan LangChain Scoring.

4. Sequence Diagram (Alur Eksekusi & Identifikasi Titik Kritis)

Deskripsi Eksekusi Pesan & Analisis Kelemahan

Diagram urutan ini memperlihatkan perjalanan waktu (*timeline*) saat pertanyaan diproses, sekaligus menyoroti 2 titik kelemahan utama dari paper asli.

Poin Urutan Eksekusi:

  • Sorotan Kelemahan 1 (Streamlit UI): Eksekusi pertanyaan dilakukan per-sesi individual (monolitik), menyebabkan bottleneck konkurensi jika ribuan pengguna masuk serentak.
  • Sorotan Kelemahan 2 (Cloud Dependency): Jika koneksi terputus atau biaya API habis pada langkah 12, sistem bawaan paper langsung mengembalikan Error Layanan tanpa adanya cadangan model luring.
  • Alur Alternatif (*alt block*): Memvisualisasikan percabangan saat API Cloud tersedia (proses berlanjut sukses) vs saat API mengalami hambatan (pesan gagal).

Sintesis Rekayasa Arsitektur

Melalui visualisasi keempat diagram di atas, kelompok kami mengusulkan solusi perbaikan berupa Dekopling Backend via FastAPI (mengatasi masalah Sequence Diagram 1) serta penambahan Hybrid Failover dengan Local SLM (mengatasi masalah Sequence Diagram 2 & Use Case Extend).
