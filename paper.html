Sistem Tanya Jawab Berbasis Chatbot Website Menggunakan Gemini AI pada Data Fiqih Kontemporer

Karya: Try Helviansyah, Nazruddin Safaat Harahap, Muhammad Irsyad, Benny Sukma Negara (UIN Sultan Syarif Kasim Riau)

1. Fokus Penelitian (Membahas Apa?)

Masalah yang Diangkat

Akses terhadap fatwa fiqih kontemporer sering kali terkendala tebalnya literatur kitab, keterbatasan waktu membaca, dan kompleksitas bahasa hukum Islam bagi masyarakat awam maupun mahasiswa. Sementara itu, problematika modern menuntut fatwa praktis yang kontekstual.

Solusi yang Dibangun: Chatbot RAG Fiqih (Text-Only)

Penelitian ini mengembangkan Question Answering System (QAS) berbasis web dengan arsitektur Retrieval-Augmented Generation (RAG) modalitas teks tunggal (text-only):

1. Korpus Data: Mengonversi 9 buku fiqih kontemporer karya Syekh Yusuf Al-Qardhawi ke format PDF.
2. Vektorisasi: Pemotongan teks (chunking) dan konversi ke vektor via model embedding-001 Google, lalu diindeks ke basis data vektor FAISS.
3. Retrieval & Generasi: Kueri teks dicocokkan untuk mengambil 3 potongan teratas (Top-3), lalu dirangkum secara kontekstual oleh model Gemini-2.0-flash melalui orkestrasi LangChain.
4. Antarmuka: Dibangun berbasis web interaktif menggunakan Streamlit.

2. Kekuatan & Keunggulan Penelitian

Validasi Ganda (Ahli & Evaluator Otomatis)

Pengujian memadukan User Acceptance Test (UAT) oleh 7 ahli fiqih (skor 89,00%) serta evaluasi kuantitatif otomatis kesesuaian rujukan menggunakan LangChain Scoring Evaluator (skor rata-rata 95,00%).

Inferensi Cepat & Penalaran Kontekstual

Penerapan arsitektur Gemini-2.0-flash memberikan waktu inferensi yang cepat (low latency) dengan pemahaman semantik bahasa alami yang memadai untuk bahasa Indonesia formal.

Grounding Fatwa Otoritatif

Jawaban dikunci (grounded) pada literatur Al-Qardhawi dengan menyertakan kutipan sumber sehingga meminimalkan bias atau fabrikasi jawaban (halusinasi AI).

3. Kelemahan & Keterbatasan Metodologis

Bias Sumber Tunggal (Single-Scholar Limitation)

Basis pengetahuan hanya bersumber dari satu figur ulama tanpa perbandingan lintas 4 madzhab besar maupun fatwa majelis tarjih/MUI lokal di Indonesia.

Ukuran Sampel Uji Terbatas (Small Sample Size)

Validasi hanya menguji 10 butir pertanyaan dan 7 responden, belum mencakup skenario pertanyaan jebakan atau kasus hukum fiqih yang ambigu (*edge-cases*).

Fokus Masalah 1 yang Dipilih

Skalabilitas Antarmuka Web Rendah (Streamlit)

Framework Streamlit memiliki kendala konkurensi bawaan karena arsitektur eksekusi ulang skrip (rerun script) yang membebani memori saat diakses serentak oleh banyak pengguna.

Fokus Masalah 2 yang Dipilih

Ketergantungan Penuh pada Cloud API Pihak Ketiga

Keterikatan (vendor lock-in) pada Google AI API mengharuskan koneksi internet aktif dan biaya pemanggilan API berkelanjutan tanpa adanya opsi arsitektur fallback model luring (on-premise) jika kuota habis atau jaringan terputus.

4. Solusi Usulan Terhadap Masalah yang Dipilih

Fokus Pemecahan: Mengatasi kendala konkurensi antarmuka Streamlit serta menghilangkan risiko ketergantungan mutlak pada Cloud API Google.

Solusi 1: Dekopling Arsitektur (FastAPI + Asynchronous Worker + Semantic Cache)

Mengatasi Masalah: Skalabilitas Antarmuka Web Rendah.

• Migrasi ke FastAPI: Memisahkan logika backend dari antarmuka visual menggunakan FastAPI dan worker Uvicorn yang mendukung I/O non-blocking untuk melayani ribuan koneksi konkuren.
• Pemisahan Frontend: Menggunakan antarmuka web statis ringan yang dapat di-hosting pada CDN tanpa membebani server komputasi.
• Caching Semantik (Redis): Kueri fatwa yang sering ditanyakan disimpan di Redis untuk merespons instan (<50 ms) tanpa memicu komputasi ulang FAISS atau LLM.

Solusi 2: Arsitektur Hybrid Failover Router Menggunakan SLM Lokal (VRAM 4 GB Ready)

Mengatasi Masalah: Ketergantungan Penuh pada Cloud API Gemini.

• Smart Router: Google Gemini 2.0 Flash tetap menjadi pemroses utama di cloud. Jika limit kuota habis (HTTP 429) atau koneksi putus, router otomatis beralih ke mesin lokal.
• Model Fallback Hemat Memori: Memanfaatkan Small Language Model terkuantisasi 4-bit seperti Qwen 2.5 3B-Instruct atau Gemma E2B / Gemma 3 4B (Q4) yang hanya mengonsumsi VRAM ~2,0–2,5 GB. Model ini dapat berjalan stabil di laptop tim dengan GPU 4 GB.
• Embedding Cadangan Offline: Menggunakan model embedding open-source lokal (paraphrase-multilingual-MiniLM-L12-v2 atau bge-small) sehingga fungsi pencarian semantik tetap bekerja tanpa internet.

Peringatan Metodologis & Batasan Fiqih
